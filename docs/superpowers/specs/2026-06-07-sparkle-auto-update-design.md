# Sparkle auto-update for bgbgone-app

**Date:** 2026-06-07
**Status:** Approved — implementing
**Author:** Arthur Ficial

## Goal

In-app automatic updates: the GUI checks a feed, downloads a newer signed build,
installs it, and relaunches — "never touch a terminal" for upgrades too. Powered by
**Sparkle 2.x**, pointed at our existing **GitHub Releases**, with the appcast feed
hosted on **GitHub Pages**.

## Why Sparkle (dependency exception)

CLAUDE.md says resist third-party deps for problems Foundation/SwiftUI solve. Auto-update
for apps distributed **outside the App Store** is not one of those — Apple ships no
updater for Developer-ID apps. Sparkle is the industry standard (Transmission, IINA,
etc.). Its update window is real AppKit chrome, so it stays within the "no fake UI"
charter. This is a deliberate, documented exception.

Squirrel.Mac (the GitHub-team updater) was considered and rejected: it is the Electron
auto-updater (Obj-C), not a fit for a native Swift app, and effectively unmaintained for
direct native use.

## Decisions (approved)

- **Framework:** Sparkle 2.x via SwiftPM.
- **Feed hosting:** GitHub Pages — `https://arthur-ficial.github.io/bgbgone-app/appcast.xml`.
- **Cadence:** automatic background checks (Sparkle's first-launch consent prompt) **plus**
  a manual "Check for Updates…" menu item.
- **Signing key:** Sparkle EdDSA private key stored in macOS Keychain **and** backed up to
  `pass` at `apple/bgbgone-sparkle-ed-private`. Public key embedded in Info.plist.
- **Verification path:** ship v0.3.2 as the Sparkle-enabled baseline, then cut a trivial
  v0.3.3 and prove the installed v0.3.2 detects + installs it (screenshotted).

## Components

### App (new, isolated)
- `Sources/Services/UpdaterService.swift` — `@MainActor @Observable` wrapper over
  `SPUStandardUpdaterController` (started automatically, automatic checks allowed).
  Exposes `checkForUpdates()` and `canCheckForUpdates`.
- `Sources/App/BgBgOneApp.swift` — `CommandGroup(after: .appInfo)` with a
  **"Check for Updates…"** `Button`, bound to the service, disabled when
  `!canCheckForUpdates`.
- `Info.plist` (source) — add `SUFeedURL` and `SUPublicEDKey`. `build-app.sh` already
  copies + version-patches this into `Contents/Info.plist`; Sparkle reads the bundle copy.
  `CFBundleVersion` is set to `.version` at bundle time and increments — Sparkle's
  comparison key.

### Signing
- EdDSA keypair generated by Sparkle's `generate_keys`. Private key in Keychain + `pass`.
  Public key string → `SUPublicEDKey`. This is **additional** to Apple notarization, which
  is unchanged.

### Bundling (`scripts/build-app.sh`)
- Copy `Sparkle.framework` (with nested XPCServices + `Autoupdate`/`Updater.app`) from the
  resolved SwiftPM artifact path into `Contents/Frameworks/`.
- Deep-sign the framework with hardened runtime + timestamp (distribution) or ad-hoc (dev)
  before signing the outer bundle, so notarization passes. Verify with
  `codesign --verify --deep --strict`.
- Build-time guard: fail if the bundled `Info.plist` lacks `SUFeedURL`/`SUPublicEDKey`
  (same spirit as the existing embedded-bgbgone version assertion — never ship an updater
  pointed at nothing).

### Release (`scripts/release.sh`)
- After notarization, run Sparkle's `generate_appcast` (resolved from the SwiftPM artifact
  `bin/`) with `--download-url-prefix` set to the GitHub Release download URL, producing
  `appcast.xml` with EdDSA signatures over the `.zip`.
- Publish `appcast.xml` (+ release-notes `.md`/`.html`) to the `gh-pages` branch.
- GitHub Pages enabled on the repo (one-time).

## Testing & verification

- **Unit:** `UpdaterService` constructs and reports `canCheckForUpdates`.
- **Build guard:** Info.plist SU keys present in the bundle (build fails otherwise).
- **Real e2e:** install v0.3.2, cut v0.3.3, run v0.3.2, screenshot Sparkle finding +
  installing v0.3.3, confirm the relaunched app reports 0.3.3.

## Known limitation

Existing v0.3.1 installs have no Sparkle and cannot be auto-updated *into* v0.3.2 — users
upgrade once manually (Homebrew / GitHub). From v0.3.2 onward every release auto-updates.
Called out in the v0.3.2 release notes.
